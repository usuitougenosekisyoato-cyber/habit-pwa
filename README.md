# 習慣トラッカー(PWA)

スマホのホーム画面に追加して使う、シンプルな習慣トラッカーです。
素の HTML / CSS / JavaScript だけで作っていて、外部のサービス・CDN・ライブラリは使っていません。
一度開けば、オフラインでも動きます。

## できること

| 機能 | 内容 |
|---|---|
| 習慣の追加 | 名前を入れて「追加」。空・31文字以上・同じ名前は追加しません |
| 毎日のチェック | 丸いボタンを押すと今日の分がオン/オフになります |
| 連続日数 | 「🔥 n日連続」と表示。今日まだチェックしていなくても、昨日まで続いていれば途切れません(「今日はまだ」と出ます) |
| 今月の記録 | 習慣を選ぶと、今月のカレンダーにチェックした日が色付きで出ます。「今月 n 日チェック(今日までの m 日中)」も表示します |
| バックアップ | JSON ファイルへの書き出しと読み込み(下で説明) |

## データの保存場所

- データは **この端末のブラウザの localStorage** に保存されます(キー名: `habit-tracker:v1`)。外部には送りません。
- そのため、次のときはデータが消えたり見えなくなったりします。大事なら先に「書き出す」でバックアップしてください。
  - ブラウザの「サイトデータ(Cookie など)の削除」をしたとき
  - 機種変更したとき、別のブラウザで開いたとき
  - iPhone で長いあいだ(目安: 数週間)アプリを開かなかったとき(Safari が保存データを消すことがあります。ホーム画面に追加したアプリでは起こりにくくなります)
- 保存データが壊れていて読めなかったときは、空の状態で始めます。このとき元のデータは消さず、`habit-tracker:v1:broken:日時` という別のキーに残します。

データの形:

```json
{
  "version": 1,
  "habits": [
    { "id": "h_xxx", "name": "散歩する", "createdAt": "2026-11-22",
      "checks": ["2026-11-21", "2026-11-22"] }
  ]
}
```

日付はすべて端末のローカル日付 `YYYY-MM-DD` です(時差で1日ずれないよう、`toISOString()` は使っていません)。

## バックアップ(書き出し・読み込み)

- **書き出す**: `habit-tracker-backup-YYYY-MM-DD.json` が端末に保存されます。
- **読み込む**: ファイルを選ぶと、次の順で進みます。
  1. このアプリで書き出した形か確かめます(`"app": "habit-tracker"`、`"format": 1`、習慣の id・名前・日付が正しいか、2/30 のような実在しない日付がないか、など)。違えば理由を表示して止まり、今のデータには触れません。
  2. 「今のデータ(習慣◯件・チェック◯回)」と「読み込むデータ(◯件・◯回・書き出した日時)」を並べて、置き換えてよいか確認します。
  3. 「置き換える」を押したときだけ置き換えます。「やめる」なら何も変わりません。
- 試し用に `sample-backup.json`(習慣3件・チェック38回、10月末から続く25日連続を含む)を置いてあります。

## スマホのホーム画面に追加する

ホーム画面に追加してオフラインで使うには、アプリが **https の URL で配信されている** 必要があります(ブラウザの決まりで、Service Worker は https か、パソコン自身の `localhost` でしか動きません)。
このフォルダの中身を、https で配信できる場所(例: GitHub Pages などの静的サイトの置き場)に置いて、その URL をスマホで開いてください。
(同じ Wi-Fi で `http://パソコンのIP:8765/` を開くと画面は出ますが、https ではないのでオフライン対応とホーム画面アプリにはなりません。)

**iPhone(Safari)**
1. Safari でアプリの URL を開く
2. 画面下の共有ボタン(□に↑)を押す
3. 「ホーム画面に追加」→ 右上の「追加」

**Android(Chrome)**
1. Chrome でアプリの URL を開く
2. 右上の「︙」メニューを押す
3. 「ホーム画面に追加」(または「アプリをインストール」)→「インストール」/「追加」

追加したアイコンから開くと、ブラウザの枠なしで全画面のアプリとして動きます。一度開いたあとは、機内モードでも開けます。

## パソコンで動かす(確認用)

```powershell
cd habit-tracker
python -m http.server 8765 --bind 127.0.0.1
```

ブラウザで `http://127.0.0.1:8765/` を開きます。止めるときは Ctrl+C です。
(`npx` などは使いません。Python の標準機能だけで配信できます。)

## テストの実行方法

計算・データの検査・保存の境目は `habits.js`(と `storage.js`)に分けてあり、Node.js 標準の `node:test` / `node:assert` でテストしています。

```powershell
cd habit-tracker
node --test
```

(`npm test` でも同じです。PowerShell で `npm` が止められたら `npm.cmd test`。)

テストの中身:
- `test/habits.test.js` … 日付(月またぎ・年またぎ・うるう年・夏時間)、追加、チェックのオン/オフ、連続日数、今月の記録、保存と読み込み、バックアップの検査
- `test/sw.test.js` … `sw.js` のキャッシュ一覧に、画面に必要なファイルがすべて入っていて、書き間違いがないか

時差でずれないことは、タイムゾーンを変えても確かめられます。

```powershell
$env:TZ='America/New_York'; node --test; Remove-Item Env:TZ
```

## アプリを更新するとき(古い画面が残らない仕組み)

**ルール: アプリのファイルを1つでも変えたら、`sw.js` の先頭の `VERSION`(例: `'v1'` → `'v2'`)を必ず上げてください。**
ファイルを増やしたときは `sw.js` の `APP_FILES` にも足してください(足し忘れは `node --test` で見つかります)。

新しい版への切り替わりは、次の順番で進みます。

1. アプリを開くと、画面はいまの版(v1)のキャッシュからすぐに出ます(オフラインでも開ける)。
2. 裏でブラウザが `sw.js` を取りに行きます(`sw.js` 自体はブラウザの通常キャッシュを使わない設定です)。中身が変わっていれば、新しい版(v2)のインストールが始まります。
3. v2 は全ファイルを、通常キャッシュを通さずサーバーから取り直して、新しいキャッシュ `habit-tracker-v2` に入れます。この間も画面は v1 のまま使えます。
4. 取り込みが終わると v2 は待機し、画面の上に「新しい版があります [更新する]」が出ます。
5. 「更新する」を押すと v2 が有効になり、古いキャッシュ `habit-tracker-v1` を削除します。
6. ページが自動で再読み込みされ、v2 の画面になります。

- 「更新する」を押さなくても、アプリを完全に閉じて開き直せば v2 に切り替わります。
- チェックの途中で画面が急に入れ替わらないよう、利用者がボタンを押してから切り替える形にしています。
- 保存データ(localStorage)はキャッシュとは別の場所にあるので、更新しても消えません。
- アプリに戻ってきたとき(画面が表示されたとき)にも、新しい版がないか確かめます。

## ファイル構成

```
habit-tracker/
├─ index.html             画面
├─ style.css              見た目(スマホ向け・ダークモード対応)
├─ app.js                 画面の処理(DOM・イベント・Service Worker の登録と更新のお知らせ)
├─ habits.js              画面に関係しない処理(DOM に触れない純粋な関数)
├─ storage.js             localStorage との読み書き
├─ sw.js                  Service Worker(キャッシュとオフライン対応)
├─ manifest.webmanifest   ホーム画面に追加するための設定
├─ icons/                 アイコン(SVG と PNG 192 / 512)
├─ sample-backup.json     読み込みを試すためのバックアップ
├─ package.json           テストの実行用(依存パッケージなし)
└─ test/
   ├─ habits.test.js
   ├─ sw.test.js
   └─ fixtures/           読み込みを断るべきファイルの例
```
